# سیسمونی نی‌نی ماه

نسخه آماده انتشار روی GitHub Pages. این بسته طوری چیده شده که محتویات آن مستقیماً در ریشه مخزن GitHub قرار بگیرد؛ پوشه اضافی `ninimah/` داخل ZIP وجود ندارد.

## ساختار فایل‌ها

```text
(index مخزن)
├── index.html
├── README.md
├── css/
│   └── style.css
├── js/
│   ├── app.js
│   └── config.js
└── assets/
    ├── favicon.svg
    └── logo-placeholder.svg
```

## آپلود در مخزن موجود

1. ZIP را استخراج کنید.
2. وارد پوشه استخراج‌شده شوید؛ فایل `index.html` باید همان‌جا دیده شود.
3. تمام محتویات داخل این پوشه را در صفحه اصلی مخزن `test` در GitHub آپلود کنید؛ خود پوشه را به‌عنوان یک پوشه تو در تو آپلود نکنید.
4. اگر GitHub پرسید فایل‌های هم‌نام جایگزین شوند، تأیید کنید.
5. لوگوی اصلی فروشگاه را با نام دقیق `logo.png` داخل پوشه `assets` آپلود کنید. تا آن زمان لوگوی جایگزین نمایش داده می‌شود.
6. در `Settings → Pages` مطمئن شوید منبع انتشار `Deploy from a branch` و شاخه `main` و پوشه `/(root)` است.
7. پس از پایان Deploy، سایت را با `Ctrl + F5` تازه‌سازی کنید.

## مدیریت و امنیت

ورود مشتری و ثبت‌نام مشتری در رابط کاربری وجود ندارد؛ فقط ورود مدیر باقی مانده است. در اولین ورود، حساب مدیر را در همان مرورگر ایجاد کنید؛ نام کاربری پیش‌فرض یا رمز ثابت در کد تعریف نشده است.

سازوکار هش PBKDF2، محدودیت تلاش ناموفق و نشست زمان‌دار حفظ شده است. با این حال، این پروژه استاتیک و بدون بک‌اند است؛ داده‌های مدیریت در مرورگر مدیر ذخیره می‌شوند و تغییرات پنل به‌صورت خودکار برای بازدیدکنندگان دیگر منتشر نمی‌شوند. برای مدیریت واقعی چندکاربره و امنیت سمت سرور، بک‌اند لازم است.

## مسیرهای فایل

صفحه اصلی از مسیرهای نسبی `css/style.css`، `js/config.js`، `js/app.js` و `assets/...` استفاده می‌کند. بنابراین مخزن باید دقیقاً ساختار بالا را داشته باشد.
